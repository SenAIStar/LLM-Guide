# 07 智能问答助理（Agent + RAG + SFT + GRPO）

RAG 不需要把每一步都交给 Agent。这里仅开放几类动态决策：要不要改写 query、走哪条检索分支、是否重排、是否再检索一次，以及证据不足时应该回答还是拒答。BM25、Dense 和 Reranker 仍是确定的检索组件，模型只负责路由和停止。

仓库保留状态机、检索融合、轨迹奖励和评估代码。它不是完整问答服务，示例问答也都是合成数据。

## 1. 做完后要留下什么

- BM25、Dense、Hybrid、Hybrid + Reranker 的固定检索基线；
- 包含 query rewrite、分支选择、补检和拒答的结构化轨迹；
- SFT 与 GRPO 的同口径对照结果；
- 可回答、无答案、版本冲突和权限不足测试集；
- 检索、轨迹、答案三层指标与失败样例。

项目价值不在于把每一步都换成 Agent。只有那些确实依赖问题和当前证据的决策才交给模型，稳定步骤继续用普通程序完成。

## 2. 状态机怎么设计

```text
classify
  -> rewrite（可选）
  -> BM25 / Dense / Hybrid
  -> rerank
  -> answer / retry once / abstain
```

每一步输出结构化 action，执行器检查 action 类型、检索分支、参数、最大动作数和最大检索轮数。[`pipeline.py`](./src/agentic_rag/pipeline.py) 还处理空 query、重复 query、未知分支和非法状态转移，异常轨迹统一进入 abstain 并保留停止原因。

## 3. 先建立固定 RAG 基线

在训练 Agent 前，先把 BM25、Dense、Hybrid 和 Hybrid + Reranker 四组基线跑稳。BM25 对编号、专有名词和精确词项常有优势，Dense 更擅长语义改写；哪一路更好由当前语料和问题分布决定。

固定文档切分、索引版本、候选数和评测集，分别记录 Recall@5、MRR 和 nDCG。没有这一步，Agent 最后即使变好，也无法判断收益来自路由还是底层检索器变化。

## 4. SFT 轨迹怎么构造

一条 SFT 样本保存原问题、改写 query、检索分支、候选文档、重排结果、最终证据、答案、引用和停止原因。高质量轨迹可以来自规则路由、强模型生成后人工修订，或对多条候选轨迹做筛选。

需要过滤循环、未知工具、越权证据、无依据回答和伪造完成的轨迹。保留少量可恢复错误，让模型学会在检索结果不足时补检；不要把所有错误步骤都删成一条“完美捷径”。

数据按文档族和问题模板切分。无答案集要包含知识库范围外问题、关键证据被删除、只有冲突版本和权限不足四种情况。

## 5. Agent 负责哪些决策

第一版只开放下面几类 action：

1. `rewrite`：消解简称、补充实体或生成检索友好的 query；
2. `retrieve`：选择 BM25、Dense 或 Hybrid 分支；
3. `rerank`：对候选做精排并选择下一步；
4. `answer`：证据充分时回答；
5. `abstain`：证据不足、冲突或越权时停止。

补检最多一次或两次，并设置总 action budget。没有预算和重复 query 检查，模型很容易用更多检索换取局部收益，成本与延迟会失控。

## 6. GRPO 奖励

同一问题在固定索引上执行多条轨迹，再组合：

- 检索奖励：gold evidence 是否进入 Top-k；
- 轨迹奖励：工具、参数、顺序和停止条件是否合法；
- 答案奖励：结论正确，引用支持对应 claim；
- 边界奖励：无答案或冲突时正确拒答/澄清；
- 效率惩罚：重复 query、无效调用和额外检索轮次。

[`rewards.py`](./src/agentic_rag/rewards.py) 展示了奖励分解和组内相对优势。各项先统一量纲，再监控它们对总 reward 的贡献，避免模型只优化最容易拿分的一项。

`configs/grpo.yaml` 是奖励与预算设计稿。实际训练要固定 VeRL 版本，把 action/observation 环境接到 rollout，并对环境返回内容做 loss mask。

## 7. 评估和归因

检索侧报告 Recall@5、MRR 和 nDCG；轨迹侧报告非法 action 率、重复 query 率、平均检索轮数和超预算率；答案侧报告正确率、引用支持率、拒答/澄清正确率和端到端成功率。

实验分三步：

1. 固定模型，比较四种固定检索方案；
2. 固定索引与工具，加入 Agent 路由；
3. 固定环境和评测集，比较 SFT 与 GRPO。

这样才能把收益分别归到检索、路由和后训练。固定减分或阈值策略可以保留为 baseline，但不能直接写成通用结论。

## 8. 失败与安全检查

至少单独分析：query 改写丢失关键实体、选错检索分支、相关证据在候选中但被 reranker 排掉、重复检索没有新增信息、引用不支持答案、该拒答时强答，以及越权 chunk 进入上下文。

文档和检索结果都按不可信数据处理。ACL 要在检索前执行；模型不能获得不必要的写操作工具；遇到权限检查、索引或引用校验失败时应 fail closed。

## 10. 简历怎么写

下面保留一份完整的简历表述，**数字不是仓库实测**。写简历前换成自己的索引版本、轨迹、模型输出和人工标注结果。

**智能问答助理｜Qwen3、Agentic RAG、BGE-M3、BM25、RRF、BGE Reranker、SFT、GRPO**

- 面向 1500 份领域文档构建 23000 个可追溯 chunk 与 3000 条问答，将 query rewrite、检索分支选择、重排、补检和拒答建模为结构化 Agent 轨迹；
- 完成 BM25、Dense、Hybrid、Hybrid + Reranker 与 Agentic RAG 五组 ablation，在 250 条可回答问题上将 Recall@5 由 Dense 的 73.2%（183/250）提升到 85.2%（213/250）；
- 基于高质量工具轨迹完成 SFT，并以 gold evidence、工具合法、答案引用和检索成本设计 GRPO 奖励，将端到端成功率由 75.2%（188/250）提升到 82.8%（207/250）；
- 构造 100 条无答案与证据冲突样本，将正确拒答/澄清由 68 条提升到 84 条；350 条完整测试轨迹中，含无效工具调用的轨迹由 30 条降至 12 条。

## 11. 面试官可能会问

**为什么不能直接断言 Dense 比 BM25 好？**

回答要点：关键词、编号和专有名词可能让 BM25 更强，语义改写可能让 Dense 更强。必须用相同数据、候选规模和指标做对照。

**什么时候值得做 Agentic RAG？**

回答要点：问题类型差异大、检索路径确实需要动态选择，或一次检索经常不足时才有价值。固定流程已经稳定时，增加 Agent 只会带来延迟、成本和新的失败点。

**怎样区分检索提升和 GRPO 提升？**

回答要点：先固定模型比较检索方案，再固定索引、工具、候选规模与解码配置比较 SFT 和 GRPO，同时报告检索、轨迹和答案指标。

**为什么限制补检次数？**

回答要点：更多检索不一定带来新证据，却会增加延迟、Token 和循环风险。用最大轮数、重复 query 与无进展检测控制预算。

**无答案为什么要单独评测？**

回答要点：只在可回答集上优化会鼓励强答。知识库范围外、证据冲突和权限不足决定系统是否可靠，必须单独报告正确拒答/澄清与错误回答率。

**Agentic RAG 多了什么安全风险？**

回答要点：分支选择错误、非法参数、循环、成本失控和外部内容诱导 action。执行器必须校验结构、权限和预算，不能把安全边界交给模型自己遵守。
